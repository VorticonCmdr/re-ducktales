# Destination explicit waits

The browser now shows the original five-by-five clear and reveal,then a separate
page flip before accepting a destination choice. Changing a choice plays the
original request36 when sound is enabled,waits seven driver counts,flips the
selector page and waits one driver count before accepting the next command.
Confirmation flips once,flushes and waits seven counts before returning36 for
Map or1 for travel. The selected transport flag changes while the selector is
drawn,before confirmation,as in the original. Cash,day,coin and RNG changes
still happen in the campaign continuation after that return.

`DestinationWaits` is independent of DOM,wall time,audio and pixels. Game supplies
its unsigned driver counter and video retraces. Wait arithmetic uses the
original unsigned32 comparison and wrapping target;source-derived wrap tests
cover the original immediate completion when a wrapped target is below the
current counter. Rendering alone keeps the old visible page for the wipe and
reuses the original EGA interleaved-row transition. That history never selects
an input or changes the simulation.

The ready flag,phase,deadline,visible choice and consumed/discarded semantic
commands are explicit in`campaign.destination` while the dialogue owns control.
The application buttons show waiting states and prevent confirmation while busy.
The keyboard still uses the existing semantic destination adapter:early commands
are counted rather than deferred into the next choice. The focused browser
scenario verifies entry/selection input rejection and the confirmation handoff.

## Verification and scope

`npm run verify:destination-waits` runs the source-byte checks,unit suite,the four
focused destination/map browser scenarios,and a real missing-Right control.
The source check requires all22 original hashes and checks the actual EGA
clear/reveal loop constants,flip callback,selection0/7,ordinary loop0/1,
confirmation flush/0/7 and resident unsigned DWORD wait helper. Independent
synthetic component clocks check the explicit51-retrace entry and seven-count
waits. These are source-derived cases,not captured native clock replays.

The new six unit cases cover transitions,early input,delayed visible selection,
Map return,Fire precedence,atomic wrap,unsigned counter overflow,invalid inputs
and the application's existing pause adapter. Existing campaign/atomic/rival
fixtures now enter the dialogue and finish its waits before continuing;their
expected day/cash/RNG values are unchanged. The legacy11-command bank comparison
uses the same semantic commands with an explicit fixture clock provider between
reads. Its original state fields remain unchanged;its map image is checksum
checked rather than a browser-pixel comparison.

The actual browser exercises Map return,reopening,flight confirmation,departure
and Restart. It checks all ten entry bands,the old highlight before the seventh
count,the completed confirmation deadline,disabled controls and exactly one
Tandy acknowledgement for request36. The original invariant labels/footer and
all36 map input/flag/pointer comparisons remain required. Omitting the actual
Right make must fail immediately at choice0 versus1,not by timeout.

The older original destination comparisons remain separate and required:
`npm run verify:destination` and`npm run verify:destination-video` compare their
five native reads each,four complete pages in total,and the captured page/cache
relationships. Their caller contexts remain conditional. They do not prove this
new Game wait integration has exact original CPU or scanout timing.

## Remaining work

Resource loading,CPU/footer drawing duration,the recurring mode1 flush/read
window and neutral input loop are not translated here. The ordinary loop0/1
bytes are checked as source,while this adapter waits for semantic commands.
No constant footer cost or captured-output-derived input period is substituted.
Native deferred system-key polling also remains open;the existing pause adapter
freezes active component waits. Exact raw-cache/video-phase alignment is not
claimed. This is explicit-wait integration,not complete destination-routine parity.

Unchanged historical Easy/Hard office event streams now fail at checkpoint1
`flight-start`:their Right and Fire arrive during the entry wipe and are counted
as early inputs. Expected states and inputs have not been rewritten or excluded.
The exploratory linked-campaign controller now waits for actual readiness so new
independent recordings can be made. Fresh carried Game/browser campaigns and the
relevant integrated gate are still required before updating the accepted main
preview. The older later bank/report timing investigations remain historical
evidence for their earlier source.
