# Expedition destination page

The browser now draws the original destination information instead of the former
partial page: four location-description lines, treasure name, two treasure
explanation lines, treasure value, travel time and the original footer. Treasure
names of24 or more characters wrap as the original does. Collected treasure
shows value0. The bank skips the treasure section. Atomic transport is drawn
only when available. These latter branches are statically inferred; they do not
have additional original screenshot coverage yet.

The selector uses the original inclusive integer EGA line routine rather than a
browser rectangle stroke. Drawing uses the original MAIN.ARC assets/font and
executable labels. LOOT.ARC's explanation lines remain authoritative and are now
retained by its decoder. Immutable completed-page commands are cached only in
the renderer; no pixels, DOM state or browser clock enter the simulation.

## Input rule

Overlay2:1e8e..1cdd checks Fire before direction. Exact reader codes3/7 wrap the
selection through two choices or three with atomic transport. Diagonals do not
change selection. Fire returns36 for Map or1 for travel. `destinationInput`
implements this rule and Game uses it for selection and confirmation. Game's
current destination adapter still supplies semantic arrow/Fire events; original
mode1 polling, flush windows and menu waits are not yet connected there.

## Reproducible evidence

`npm run verify:destination` requires ignored originals/local captures and fails
on missing/corrupt evidence, changed tools, zero/missing reads or comparisons.
[The manifest](../reference/destination.json) pins33 local artifacts and the
535-file capture producer on04358b0. The fresh original capture uses the fixed
`reference/map-notice-inputs.json` schedule after natural security/map entry;
no original CPU/memory writes or restores are used.

The checker validates all22 original hashes, the complete8368-byte relocated
map overlay, producer ZIP/Git sources, capture success and emulator cleanup.
It then carries the ordinary-key table and selection through all five original
menu reads, checking input AX, all128 flags at flush/reader boundaries and the
final flight return. All three authored notice sequences must be consumed.
Missing choice and confirmation makes must fail. Source-derived Fire-precedence,
diagonal and atomic-wrap branches are checked separately from native cases.

Two completed pages (read0 Map selection and read4 flight selection) compare all
64000 RGBA pixels exactly. The choices come from the independent input stream.
Location/treasure resource IDs, day, money, collected status and travel time are
captured **internal caller arguments before destination drawing**. This is a
conditional presentation/reader segment, not independently replayed campaign
resource assignment, RNG or travel arithmetic. Expected pictures do not supply
those arguments or drive any inputs. Four altered-pixel/missing-description
controls must fail; real missing-snapshot/corrupt-picture setup controls must
fail and exact restored fixtures must pass.

`npx playwright test tests/browser/destination.spec.js tests/browser/map-pointer.spec.js`
exercises fresh application→office→security→map→destination→flight choice→departure
and Restart using real browser controls. The fresh BIOS0 route selects Bolognia,
while the native capture selects the Great Outback. The actual browser compares
four invariant label regions and the complete footer against the original;
it does not claim that the differing whole pages are the same. The separate
map test still requires all36 original input/flag/pointer comparisons.

All three focused browser cases,the complete native command,117 unit checks and
