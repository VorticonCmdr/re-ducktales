# Security-aware Easy jungle treasure

The browser completes Okeefadokie from a fresh supported build through original
security and two real bank/office trips. It flies/crashes/repairs into the jungle,
collects the treasure, returns to the map, remains idle without advancing rival
state, shows the original collected-treasure notice and returns without another
award. The player finishes on day 17 with 1050 dollars, one life, 860 jungle input
samples, 907 presentations and seed55093. The value is1000 plus a50-dollar pickup.
The per-frame browser case additionally verifies Restart after the recorded route.

## Independent evidence

The [manifest](../reference/security-jungle-treasure.json) keeps player events,
expected snapshots and artifact identities separate. All27 complete application
snapshots and all 320x200 pixel hashes match in a fresh keyboard-controller run and
in a second browser driven only by70 recorded DOM events. Independent Game replay
from original startup matches all 27 snapshots, consumes every event and validates
all 74 flight presentations, with zero flag aliases and no exploratory tail. The
recorded route ends on the map after the duplicate notice; it is not a campaign.

The capture command deliberately exits with an exploratory error after saving
its data. Capture alone is not acceptance. The accepted completion declaration
changes only environment metadata; player events, observation times and expected
snapshots remain byte-identical to the original capture. Source archives pin 127
capture files to 98f0cb6 and128 fresh-browser files to 805f950. Original assets remain
in ignored game/ and all generated pictures, traces and model states stay local.

The shared recorded-browser adapter now recognizes the explicit jungle endpoint.
Its Hard default still requires the original ending. A fresh full Hard regression
retains all 28 exact state/pixel checkpoints and4140 DOM events through all four
families to its existing day 31 result. Its126 source identities are also retained;
historical capture and browser producer revisions remain unchanged.

## Strict verification

```
npm run verify:jungle
npm run verify:security-jungle-treasure
```

The first command retains all existing native/conditional jungle checks and now
requires both recorded entry and treasure verifiers. The focused command runs
the strict treasure verifier, both actual browser modes and a missing-Right-key
browser negative. Missing/corrupt originals or private fixtures, zero/missing
checkpoints, unconsumed inputs, unsupported paths, rendering errors, skips and retries
fail. The verifier requires the build identity, 49 artifacts and all three source
archives. It checks the recorded input profile against its unchanged legacy
source and compares independent browser progress and event counts.

Five comparison negatives reject wrong security input, an altered expected state,
a missing checkpoint, a changed browser pixel hash and an omitted browser
checkpoint. The actual-browser negative omits the first jungle Right make and
fails at input120, after entry and the first80 samples still match. The original
Hard missing-choice negative remains valid. A successful native conditional
check is not reported as a complete original-level comparison.

Separate setup negatives removed and corrupted the derived input80 PNG. Both
failed at the required fixture checks, the original checksum was restored and
the positive verifier passed again. The recipe and logs remain in the private
verification directory; routine verification does not mutate any fixture.

Private artifacts are in `.local/security-jungle-treasure-01/`,
`.local/security-jungle-treasure-accepted-01/` and
`.local/security-jungle-treasure-verification/`. Native whole-level timing, other
jungle routes and arbitrary campaign finishability remain unproven. Main remains
054ac66; mountain-ascent, lightning, alternate Hard routes, Easy campaign migration
